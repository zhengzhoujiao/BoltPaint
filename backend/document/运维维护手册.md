# BoltPaint 后端运维维护手册

本文档面向系统管理员和运维人员，涵盖了环境安装、Docker 部署、日常维护、多环境切换及故障排查的操作指南。

---

## 1. 部署与安装

### 方法 A: Docker 部署 (推荐)

我们采用了 **“代码环境封装”**、**“运行时变量注入”** 与 **“Nginx 反向代理”** 结合的设计。

**部署架构**:
- **Nginx**: 作为统一入口（80 端口），负责流量转发与静态资源服务。
- **Backend (Python)**: 处理业务逻辑，不直接暴露给宿主机。
- **MongoDB**: 数据库持久化。

**准备工作**: 确保已安装 Docker 和 Docker Compose。

**部署步骤**:
1. **构建镜像**: 在 `backend` 目录运行 `docker build -t bolt-painting-backend .`
2. **配置文件**: 在 `docker/` 目录下创建 `.env` (参考 `.env.example`)。
3. **启动服务**: 在 `docker/` 目录下运行 `docker-compose up -d`。
   > [!NOTE]
   > 启动后，API 将通过宿主机的 `API_PORT` (默认 80) 进行访问。Nginx 会自动处理 `/static/` 和 `/generated/` 路径下的图片。

### 方法 B: 本地 MongoDB 安装

如果你不使用 Docker 运行数据库：
- **Windows**: 下载 MSI 安装包 -> Complete 安装 -> 勾选 "Install MongoDB as a Service" -> `net start MongoDB`。
- **Docker (只跑数据库)**: `docker run -d -p 27017:27017 --name mongodb mongo`。
- **云数据库**: 使用 MongoDB Atlas 获取连接字符串。

## 2. 环境管理 (Multi-Environment)

系统支持三套标准环境：`dev` (开发)、`test` (测试)、`prod` (正式)。

### 切换环境
1. 修改宿主机的 `.env` 文件中的 `APP_ENV=prod` (或 test/dev)。
2. 重启容器：`docker-compose up -d`。

---

## 3. 运维常用命令

### 容器管理
- **查看状态**: `docker-compose ps`
- **查看实时日志**: `docker-compose logs -f backend`
- **重启后端**: `docker-compose restart backend`
- **重启 Nginx**: `docker-compose restart nginx`
- **停止并清理**: `docker-compose down`

### 数据库维护
- **自动初始化**: 如果需要手动触发示例数据注入：
  ```bash
  docker exec -it bolt_painting_backend python database/init_db.py
  ```
- **备份数据库**:
  ```bash
  docker exec -it mongodb mongodump --out /data/db/backup_$(date +%F)
  ```
- **恢复数据库**:
  ```bash
  docker exec -it mongodb mongorestore /data/db/backup_YYYY-MM-DD
  ```

## 4. 故障排查 (Troubleshooting)

### API 无法访问
1. 检查容器状态：`docker ps`。
2. 检查 80 端口占用（或你配置的 `API_PORT`）：`netstat -ano | findstr :80`。
3. 检查 Nginx 日志：`docker-compose logs nginx`。
4. 检查 `.env` 中的 `CORS_ORIGINS` 配置。

### 数据库连接失败
1. 确保 `mongodb` 容器处于 `Up` 状态。
2. 检查密码是否匹配（`.env` 中的 `MONGODB_URL` 与初始化密码）。

### MongoDB 安装/启动问题
- **服务无法启动**: 检查 `mongod.log` 日志。
- **权限不足**: 请以管理员身份运行命令行。
